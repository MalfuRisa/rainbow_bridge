## 2. 已确认问题与处理要求

### F1／P1：富文本的外部图片、视频封面会漏过检查

位置：`biz/service/release_snapshot.go:25`、`rewriteRichText`（第276行起）。

目前正则只识别带引号的 src/href，下面五种输入都能经过正常 Service 新增配置、锁版、创建版本，并返回成功：

```html
<img src=https://cdn.example.com/a.png>
<img srcset="https://cdn.example.com/a.png 1x, https://cdn.example.com/b.png 2x">
<video poster="https://cdn.example.com/poster.png"></video>
<img src="//cdn.example.com/a.png">
<div style="background-image:url(https://cdn.example.com/a.png)"></div>
```

五次结果都是资源数量0、外部提示空列表，外部媒体地址仍在快照里。别人更换外站内容后，这些页面内容仍会变化，与 PRD“外部媒体或无法可靠解析的嵌入资源应拒绝创建”的要求冲突。这不是测试工具打错 URL，是隔离数据库上真实执行创建流程后的结果。

处理要求：按 HTML 标签和属性边界解析，并覆盖 srcset、poster、相对协议地址、样式媒体引用等；不支持可靠处理的形式明确拒绝，不能悄悄当作普通文字。受管引用的捕获、重写、读取渲染要用一致规则，普通业务超链接与嵌入媒体应区分。补上述五项拒绝测试及合法受管媒体往返测试，不能只在正则后面继续补几个特殊字符串。

### F2／P2：不同范围可能被当成同一请求，返回别的范围的发布结果

位置：`biz/service/release_service.go:785—790`，`releaseFingerprint`。

当前把字段用 `|` 拼接后计算摘要，但环境键和渠道键没有禁止该字符。以下两个合法范围会得到相同请求指纹：

- 请求一：环境 `a|b`，渠道 `c`。
- 请求二：环境 `a`，渠道 `b|c`。

使用同一个 request_id、相同版本及其他字段，先创建请求一，再创建请求二，第二次被当作幂等重放：请求的是 `a / b|c`，返回却是 `a|b / c`，并且 replayed=true。按 PRD，不同请求内容应返回409冲突，不能告诉调用方另一套配置的操作“已经完成”。

处理要求：使用固定字段结构的规范 JSON 或带长度的编码后再求摘要；相同规则用于创建与切换。补跨字段边界碰撞测试，以及同一请求真正重放的正向测试。

### F3／P2：前端“确认同一请求”只保留编号，没有保留原请求内容

位置：`vue/src/components/release/ActivateReleaseDialog.vue:38—40、74—87`；创建弹窗也需要一并检查相同组织方式。

激活弹窗的 expected revision 从全局 store 实时计算。独立加载实际 Vue 组件脚本，受控模拟一次响应丢失，再让后台状态刷新，随后调用“确认结果”：

```text
同一个 request_id：true
第一次 expected_active_revision：7
确认时 expected_active_revision：8
```

编号相同、内容却变了，后端正确的指纹校验会将它判为不同请求，原结果就无法按原方式确认。原因、目标版本等也不能在重放时重新读取可编辑表单。该复现是实际组件逻辑＋模拟 API，不是完整浏览器网络复测。

处理要求：首次提交时固定整份操作 payload；确认／重试原操作必须原样发送，只允许重新输入凭据。修改目标、原因或 revision 应作为明确的新操作。来源冻结状态后来改变，也不能在前端挡住对已提交创建结果的确认。补丢响应、后台刷新、字段编辑、同请求确认的页面测试。

### F4／P2：快速切换 A→B→A，旧请求会覆盖最新页面状态

位置：`vue/src/stores/release.ts:51—68`，同类校验也用于 active 和 loadMore。

store 只检查返回结果所属范围是否等于当前范围，没有区分同一范围的不同请求批次。用实际 Vue／Pinia store 控制返回顺序，先让第一次 A 请求挂起，切到 B，再切回 A，并让第二次 A 请求完成；最后放回第一次 A 的旧响应：

```text
旧响应返回前：new-a
旧响应返回后：old-a
```

因此用户回到 A 时，已经看到的新版列表和生效状态仍可能被旧响应盖回去。后端 CAS 可阻止部分误操作，但页面展示本身已违反“不串状态、不用旧响应覆盖当前状态”的要求。该复现为 store 逻辑测试，未冒充浏览器场景。

处理要求：范围变化／刷新时生成请求批次号或取消旧请求；列表、active、分页、loading/error 均只能由当前批次更新。补 A→B、A→B→A、同范围新旧请求乱序三种场景。

### F5／P2：源存储变化后，已经创建成功的版本不能幂等确认

位置：`biz/service/release_service.go:63—70`，早于第86行附近的已提交结果查询。

隔离实测：本地创建 v1.0 成功后，把当前来源存储配置改为 MinIO，再带原 request_id 和完全相同请求确认结果，返回 `RELEASE_STORAGE_UNSUPPORTED`，没有返回已经提交的快照。

本阶段不支持从 MinIO 新建快照是约定内限制，但 PRD 同时明确：已提交结果的幂等确认不依赖当前来源存储类型或当前冻结状态。现在存储判断放在幂等查询之前，破坏了这一条。测试没有连接 MinIO，也不需要连接它就能复现提前拒绝。

处理要求：先在协调内查询、比对已提交结果，只有确定需要新建时才验证源存储能力。快照目录初始化也不应成为确认已提交元数据的前置副作用。

### 7.2 F1剩余问题一：带引号的属性值里出现 >，后面的媒体属性就不检查了

这是一段合法HTML，alt文本就是大于号。扫描器却在引号尚未结束时遇到 `>` 就停止读取属性，随后把标签扫描提前结束，漏掉后面的src。

### 7.4 F4剩余问题：旧请求的finally提前关闭新请求的加载态

位置：[release.ts:91](D:/kylin/rainbow_bridge/vue/src/stores/release.ts:91)、[release.ts:111](D:/kylin/rainbow_bridge/vue/src/stores/release.ts:111)。

当前beginBatch把pending归零，新批次请求再加1，这一步合理。但loadFirstPage和loadMore的finally无条件执行 `pending = max(0, pending - 1)`，没有核对批次。try/catch中的return仍会执行finally。

使用真实Vue/Pinia store，API响应由可控Promise替身提供：

1. 第一次A列表请求保持未返回。
2. 切到B，B列表也保持未返回，此时loading=true。
3. 只放回旧A请求，B仍未返回，loading立即变为false。
4. 放回B后loading仍为false。

这不会再把A列表写入B，但页面可能提前显示“暂无版本”或允许继续加载，与“loading只统计当前批次”的修复目标相反。现有页面回归是在新A已经完成后才放回旧A，所以没有覆盖这条时序。

要求：只有请求仍属于当前批次时才扣减当前计数，或按批次保存独立计数；同时修正首页和分页finally。补“旧请求先结束，新请求仍在途”的成功与失败时序测试，并保留已有A→B→A数据隔离测试。

### 8.2 F1-c／P1：CSS引号内的右括号仍导致整项媒体引用漏检

研发回传及交付文档§4.3写“CSS url的引号内也不再被右括号截断”，但当前代码并未实现这条：

位置：[release_html.go:259](D:/kylin/rainbow_bridge/biz/service/release_html.go:259)，scanReleaseCSSURLValue的带引号分支仍有 `content[index] != ')'`；第276—277行遇到空值后直接不返回引用。

最小输入：

```html
<div style='background-image:url(")banner.png")'></div>
```

这是合法CSS，相对图片文件名以右括号开头。与HTML属性中的大于号一样，CSS带引号字符串中的右括号属于地址内容，不是url函数的终止符。

实际独立验证：

1. AddConfig→锁版→CreateRelease→固定版本RuntimeRelease完整Service链路成功，返回原样CSS，资源数0、提示为空。期望“相对嵌入媒体必须拒绝”的断言失败。
2. 真实Chromium在 `https://review.invalid/` 页面解析同样CSS，计算样式为 `url("https://review.invalid/)banner.png")`，并实际发起该图片请求。请求被本机Playwright路由拦截，没有访问外网。

根因：读取带引号url值时，第一个字符恰是右括号，循环立即停止；随后把这项引用当空值丢弃。因此它不是只有一条交付说明写错，而是仍会放过未受快照管理的媒体。

影响：固定版本仍会依赖快照目录之外、可变化的相对图片，违反既定资源完整性契约。保持F1/P1未关闭；不涉及前端加载态，也不否定上面三个修复。

- 在style属性及style块补右括号开头的相对媒体拒绝测试，并补合法受管媒体带括号query/fragment的往返测试；保留现有HTML、srcset与普通超链接行为。
